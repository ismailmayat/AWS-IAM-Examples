# Quick Start Guide

Get up and running in 30 minutes!

## ⚠️ Cost Warning

This example creates billable AWS resources:
- **Hourly Cost:** ~$0.33/hour (~$8/day)
- **Monthly Cost:** ~$237/month if left running
- **Largest Cost:** NAT Gateways ($99/month)

💡 **Remember to clean up when done!** See [Cleanup](README.md#cleanup) in the README.

## Prerequisites Checklist

- [ ] AWS CLI installed and configured (`aws configure`)
- [ ] kubectl installed
- [ ] eksctl installed
- [ ] Docker installed and running
- [ ] Confluent Cloud account created
- [ ] Kafka cluster created in Confluent Cloud

This example will create the following AWS resources:

| Resource | Quantity | Cost/Hour | Cost/Month |
|----------|----------|-----------|------------|
| EKS Control Plane | 1 cluster | $0.10 | ~$73 |
| EC2 Instances (t3.medium) | 2 nodes | $0.08 | ~$61 |
| NAT Gateways | 3 (one per AZ) | $0.14 | ~$99 |
| EBS Volumes (gp3) | ~40 GB total | - | ~$3 |

### Free/Minimal Cost Resources
- IAM Role and Policies (free)
- Pod Identity Association (free)
- ECR Repository (~$0.10/GB for storage, ~$0.02/month for this image)

- Use 1 NAT gateway instead of 3 (saves ~$66/month, but less resilient)
- Use spot instances for worker nodes (saves ~$40/month, but can be terminated)
- Delete resources immediately after testing (see [Cleanup](README.md#cleanup))

## Step-by-Step Setup

### 1. Configure Confluent Cloud (5 minutes)

**Enable AWS Outbound Identity Federation first:**
1. Open [AWS IAM Console](https://console.aws.amazon.com/iam/)
2. Go to **Access management** → **Account settings**
3. Find **Outbound identity federation** section
4. Click **Enable** (if not already enabled)
5. AWS generates URLs with a unique UUID - save these:
   - **Issuer**: `https://{UUID}.tokens.sts.global.api.aws`
   - **JWKS URI**: `https://{UUID}.tokens.sts.global.api.aws/.well-known/jwks.json`

**Note:** The UUID is NOT your AWS account ID - it's a unique identifier generated by AWS.

Get your AWS account ID (needed for identity pool):
```bash
aws sts get-caller-identity --query Account --output text
```

**In Confluent Cloud Console:**
1. Go to **Accounts & Access** → **Identity providers** → **Add provider**
2. Select **OAuth/OIDC**
3. Set:
   - **Issuer:** Use the UUID-based URL from AWS (e.g., `https://12345678-1234-1234-1234-123456789abc.tokens.sts.global.api.aws`)
   - **JWKS URI:** Use the UUID-based JWKS URL from AWS
4. Create an **Identity pool** with Pool ID = your AWS account ID (12 digits)
5. Grant permissions: **Data access** → Add role binding for the identity pool

### 2. Set Up AWS Infrastructure (20 minutes)

```bash
chmod +x setup-aws.sh
./setup-aws.sh
```

☕ This creates the EKS cluster, IAM role, and ECR repository. Takes 15-20 minutes.

### 3. Configure Your Application (1 minute)

Edit `kubernetes/configmap.yaml`:

```yaml
BOOTSTRAP_SERVERS: "pkc-xxxxx.us-west-2.aws.confluent.cloud:9092"  # From Confluent Cloud
LOGICAL_CLUSTER: "lkc-xxxxxx"                                       # From Confluent Cloud
AWS_ACCOUNT_ID: "123456789012"                                      # Your AWS account
```

Apply the config:
```bash
kubectl apply -f kubernetes/configmap.yaml
```

### 4. Build and Deploy (3 minutes)

```bash
# Build and push Docker image
chmod +x build-and-push.sh
./build-and-push.sh

# Deploy to EKS
chmod +x deploy.sh
./deploy.sh job
```

### 5. Verify It Works (1 minute)

```bash
# Watch the logs
kubectl logs -n confluent-producer -l app=confluent-producer -f
```

Expected output:
```
✅ Got token (expires in 3600s)
✅ Message delivered to test_topic[0] @ offset 42
✅ SUCCESS! All messages produced using AWS IAM authentication
```

## Common Issues

### "Authentication failed"
- Double-check the Issuer URL in Confluent Cloud matches the UUID from AWS (not your AWS account ID)
- Verify identity pool ID equals AWS account ID

### "Unable to locate credentials"
- Pod Identity association might not be created
- Run: `source .aws-config && aws eks list-pod-identity-associations --cluster-name "$CLUSTER_NAME" --region "$AWS_REGION"`

### "Not authorized to access topics"
- Add role binding in Confluent Cloud → Cluster → Data access
